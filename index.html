How to use this roadmap

Rule: do not rush to “hacking tools.” Your foundation is the skill that makes every security tool understandable.

Study
Learn the concept and vocabulary.
Practice
Use a legal sandbox or your own lab.
Build
Create something that proves the skill.
Document
Keep notes, screenshots, commands and lessons learned.

Suggested rhythm: 60–90 minutes/day, 5 days/week. Slow and consistent beats trying to finish everything at once.

PHASE 0 — Computer Fundamentals

~2–4 weeks

Goal: understand what a computer actually does.

Hardware: CPU, RAM, storage, motherboard, GPU, peripherals
Binary, hexadecimal, bits/bytes, files and processes
Operating systems, kernels, applications, drivers
Filesystems, permissions, users and processes
Virtualization and virtual machines

Checkpoint: explain what happens from pressing a power button to opening a web page.

PHASE 1 — Networking

~3–6 weeks

Goal: understand how machines communicate.

OSI and TCP/IP models
Ethernet, MAC addresses, ARP
IPv4/IPv6, subnetting, CIDR
TCP vs UDP, ports and sockets
DNS, DHCP, HTTP/HTTPS, TLS
NAT, routing, firewalls, VPN concepts
Read packet captures in Wireshark

Checkpoint: capture a DNS + HTTP/HTTPS conversation in your own lab and explain each major packet.

PHASE 2 — Linux

~3–5 weeks

Goal: become comfortable living in a terminal.

Navigation, files, pipes, redirects and text processing
Users, groups, permissions and sudo
Processes, services, logs and package management
SSH and basic networking commands
Bash scripting fundamentals
Complete OverTheWire Bandit

Checkpoint: set up a Linux VM and administer it from the command line without relying on a GUI.

PHASE 3 — Windows + Active Directory

~3–6 weeks

Goal: understand the dominant enterprise endpoint environment.

Windows architecture, users, groups and permissions
PowerShell basics
Event Viewer, Windows logs and Defender concepts
Services, scheduled tasks and registry basics
Active Directory: domain, DC, OU, GPO, Kerberos, LDAP

Checkpoint: explain how a domain login works and where an administrator would investigate suspicious activity.

PHASE 4 — Programming + Automation

~4–8 weeks

Goal: write small programs instead of depending on someone else's tool.

Python syntax, variables, functions, loops and data structures
Files, JSON, exceptions and modules
HTTP requests and APIs
Regular expressions and parsing
Git: clone, branch, commit, diff, merge and push
Build 3 small security-related utilities for your own lab

Checkpoint: read unfamiliar Python and modify it safely.

PHASE 5 — Security Fundamentals

~3–5 weeks

Goal: learn the language and models used across security.

CIA triad, assets, threats, vulnerabilities and risk
Authentication vs authorization
Least privilege, defense in depth, zero trust
Hashing, encryption, digital signatures and PKI
Vulnerability management and patching
Logging, monitoring, detection and incident response
Read NIST CSF 2.0 at a high level

PHASE 6 — Hands-on Cybersecurity

~6–10 weeks

Goal: connect theory to controlled practice.

Complete TryHackMe Pre Security
Complete TryHackMe Cyber Security 101
Learn Nmap concepts in authorized labs
Learn Wireshark packet analysis
Learn basic vulnerability assessment
Learn web security fundamentals with PortSwigger labs
Write a report for every substantial lab

Portfolio Projects

  1. Home lab diagram: document your VMs, network segments, services and purpose.
  2. Packet-analysis report: investigate a provided/sample capture and explain the traffic.
  3. Linux hardening report: configure a lab Linux system and document security changes.
  4. Windows investigation: analyze logs from a controlled scenario and write a timeline.
  5. Web-security report: complete PortSwigger labs and explain the vulnerability, impact and remediation.
  6. Python automation: build a benign log parser, IOC formatter, or lab inventory tool.
  7. Capstone: build a small isolated enterprise-style lab and produce an assessment + remediation report.

Ethics & Safety

Practice boundary: only test systems when you own them or have explicit authorization. The roadmap teaches security skills in controlled environments; it is not permission to access someone else's account, device, network, or website.
  • Use CTFs, training labs, local VMs and intentionally vulnerable targets.
  • Keep personal accounts and real-world targets out of experiments.
  • When learning a technique, learn the defensive side and remediation too.
  • Keep a lab journal: objective → environment → observations → evidence → conclusion → fix.
